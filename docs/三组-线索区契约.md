# 线索区（Leads）契约 v0.1

目的：让 279 条待核实的媒体候选**看得见**，但永远不冒充「已核实事件」。
一句话原则：**线索可以公开，但必须让读者一眼知道它不是已核实内容，并且在机器可读层面也不进任何「已核实」统计。**

## 1. 什么记录进线索区

`content/events/*.json` 里 `status !== "published"` 的全部记录。

按来源再分两类，页面上必须显示对应标签：

| 条件 | 标签 | 含义 |
|---|---|---|
| `evidenceGrade = "secondary_only"` | 媒体线索 · 未核官方原文 | RSS 抓到的媒体报道，只做了标题/可达匹配 |
| `evidenceGrade ∈ {single_primary, multi_independent}` 且未发布 | 待核原文 | 有一手来源线索，但原文逐项核对未完成 |

## 2. 导出物（构建期，不入 content/）

`scripts/ci/derive.mjs` 额外产出 `dist/clues/index.json`，元素字段**只允许**这些：

```
id, title, summary(≤160字), occurredAt, firstReportedAt,
category, region, sourceDomain, sourceUrl, evidenceGrade, statusLabel
```

**禁止字段**：`scores`（任何维度或总分）、`trendLinks`、`forecastRefs`、`credibility`、`verification`。
理由：线索区一旦出现分数，读者就会当成排名；出现关联就会污染趋势证据链。

## 3. 页面

- 单页 `/clues/`（**不做单条详情页**，避免搜索引擎把 279 条未核实内容抓成文章页）。
- 默认按 `occurredAt` 倒序；支持按分类、地区筛选；**不提供重要度/可信度排序**。
- 每行：标题（外链原站，`rel="nofollow noopener"`）、日期、来源域名、标签徽标。
- 页首固定横幅：`以下为待核实线索，未经过官方原文核对，不构成结论，也不计入「已核实」数量。`
- 页脚固定口径说明：`线索数 = 库内未发布记录数；已核实数 = 通过发布校验的 published 数。两者互不换算。`
- `<meta name="robots" content="noindex,follow">`（**待一组拍板**：我建议 noindex，理由同上；要 SEO 就改成 index 但横幅不能撤）。

## 4. 计数口径（硬要求）

- 首页、事件页、趋势页、异军突起页的「已核实/发布」计数**不得包含线索**。
- `rankings`（重要度/置信度/热度/时间）**只由 published 生成**，线索不参与。
- 趋势 `evidenceRefs`、判断 `support`、异军突起 `events[]` **不得引用线索 ID**。
- 页面上必须**分别**显示两个数，不允许只显示合计数。

## 5. 泄漏门禁改造（最关键的一条）

现在 `scripts/ci/leakcheck.mjs` 的逻辑是「dist 里出现任何非 published ID 即失败」，线索区会正面撞上它。改法是加**受限豁免**，不是关掉检查：

1. `ALLOW_PREFIX = ['clues/']`：只豁免 `dist/clues/` 下的文件。
2. 豁免文件必须同时满足三条，缺一条即失败：
   - 文件名在 `clues/` 下；
   - 内容含标记串 `data-lead-region="true"`（HTML）或 `"statusLabel"`（JSON）；
   - 内容含中文串 `媒体线索` 或 `待核原文`。
3. JSON 里**不得出现** `"status":"pending"`：导出时把状态投影为 `"status":"lead"`。这样现有 `pendingStatusHits` 检查不需要放宽。
4. 其余所有路径仍是零容忍。**反例必测**：把 `ev_ai-dc-power-161gw` 塞进 `dist/events/index.html` → 必须 exit 1。
5. 把 `clues/` 里塞一条 published 事件 → 也应告警（线索区不该出现已核实内容）。

## 6. 明确禁止

- 线索页出现「已核实」「可信度 中/高」「单一官方来源」等徽标；
- 线索进入首页头条、事件列表主表、异军突起证据、趋势证据、判断支撑；
- 用线索数充当「每周几百条」的交付数字向用户汇报时**不加限定词**。

## 7. 验收条目（三组按此复测）

- L1 `/clues/` 200，条数 = 库内 pending 数（当前 279）。
- L2 页面含横幅与页脚口径句，机器可读标记齐全。
- L3 首页/事件/趋势/异军突起四页的已核实计数 == published 数（当前 70），不含线索。
- L4 `leakcheck` exit 0，且反例（pending ID 注入 events/index.html）exit 1。
- L5 `clues/index.json` 无 `scores`/`trendLinks`/`forecastRefs` 字段。
- L6 每条外链可点、`rel` 正确、域名与 `content/` 一致。
- L7 390 宽无横向溢出，双主题可读。
- L8 线索排序只按时间；不存在重要度排序入口。

## 8. 回退

任何一条 L1–L5 失败 → 线索区整体下线（构建时开关 `ERA_CLUES=0`），公开站回到只有已核实内容的状态，不做局部降级。
